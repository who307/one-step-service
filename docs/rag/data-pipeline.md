# 수집·색인·갱신

## 현재 파이프라인

1. 관리 API 또는 선택적 스케줄러가 공고 ID를 전달한다.
2. 온통청년 API에서 최신 자료를 조회한다. 프론트 표시용 캐시를 원본으로 사용하지 않는다.
3. 원본 JSON과 정리된 전체 본문을 확보한다.
4. 본문 및 파이프라인 설정을 비교한다. 같으면 `UNCHANGED`로 끝낸다.
5. 섹션별 청크를 만들고 OpenAI에 임베딩을 요청한다.
6. 원본·버전·청크를 저장한 뒤 활성 버전을 전환한다.
7. 실패 시 안전한 오류 상태를 남기고 이전 성공 버전은 유지한다.

## 본문·청크

`## 참여 대상` 같은 제목과 해당 필드 값을 보존한다. 청크 본문에는 공고 제목과 섹션을 포함한다. 참여 대상에 연결된 추가 자격·참여 제한을 같은 섹션에 둔다. 값이 없는 API 필드는 새로 지어내지 않는다.

너무 긴 섹션은 제한된 길이로 추가 분할한다. 분할 크기와 겹침을 바꾸면 파이프라인 버전을 바꾸고 재평가한다. 매우 긴 자격 항목은 인접 청크까지 필요한지 평가 데이터로 확인한다.

## 자동화 범위

첫 버전의 스케줄러는 설정한 공고 ID의 **갱신**을 처리한다. `RAG_SYNC_ENABLED=false`가 기본이다. 외부 기관 게시판에 새 글이 올라오는 것을 자동 발견하는 기능은 아직 포함하지 않는다.

확장 순서는 다음과 같다.

```text
온통청년 목록을 정기 조회 → 신규 ID 발견 → 처리 작업 등록
→ 본문 수집 → 변경 판별 → 임베딩 → 활성 버전 교체
```

API에 등록되기 전의 기관 게시글을 발견하려면 별도로 그 기관의 목록 API·RSS·게시판을 확인해야 한다. 지정한 출처에서만 수집하고, 사이트별 본문 추출기를 검증한다. PDF/HWP/OCR은 별도 후속 작업이다.

운영 확장 시 작업 중복 방지·제한적 재시도·실패 작업 조회를 갖춘다. 일시적으로 목록에서 빠진 공고를 즉시 삭제하지 않는다. 서버가 꺼져 있는 동안 로컬 스케줄러는 실행되지 않는다.
