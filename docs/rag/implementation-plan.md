# 구현 단계와 완료 조건

각 단계는 코드와 실제 검증 결과로 완료 여부를 판단한다. 문서 작성 자체를 기능 완료로 세지 않는다.

| 단계 | 완료 조건 |
|---|---|
| 원문 확보 | 3개 공고를 실제 API에서 조회하고 길이 제한 없는 본문과 원본 저장 가능 |
| DB·버전 | migration 적용, 재실행 중복 없음, 갱신 실패 시 기존 자료 유지 |
| 분할·임베딩 | 긴 내용 보존, 추정값 제외, 응답 순서·차원 검증 |
| 검색 API | 공고·활성 버전 격리, 입력 검증, 미색인/오류 구분 |
| 검색 평가 | 고정 질문의 근거 검색 및 지연 보고서 생성 |
| 주기 갱신 | 선택된 공고 갱신을 설정으로 활성화 가능 |
| 팀원 연결 | 문서화된 계약으로 근거와 출처를 LLM에 전달 |

## 후속 범위

- 135개 전체를 발견·등록하는 수집 작업
- 공식 HTML·첨부파일 수집
- 최종 답변의 원문 전체 전달 vs RAG A/B 비교
- small vs large 검색 품질·비용 비교
- 재정렬·키워드 결합·근사 검색 인덱스(필요성이 측정될 때)

## 실제 검증 기록

실행한 명령, 결과 파일, 실패·미실행 항목은 [evaluation.md](evaluation.md)와 최종 작업 보고에 남긴다. 실제 측정 전 정확도·비용·지연 수치를 작성하지 않는다.
