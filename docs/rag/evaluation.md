# 검색 평가와 RAG 전후 비교

## 지금 실행할 수 있는 평가

`scripts/rag-evaluate.py`는 3개 공고 × 5개 질문을 검색 API에 보낸다. 12개는 기대 섹션이 있는 질문, 3개는 사람이 근거 누락을 검토할 질문이다.

```bash
python3 scripts/rag-evaluate.py --dry-run
python3 scripts/rag-evaluate.py --repeats 3 --model-label text-embedding-3-small/1536
```

| 값 | 의미 |
|---|---|
| sectionHitRate | 기대 섹션 중 하나 이상이 상위 K개에 있는 양성 질문 비율 |
| scopeMismatches | 응답 공고 ID 또는 근거 출처가 대상 공고와 맞지 않는 실행 수 |
| p50/p95 | 성공한 검색 HTTP 요청의 전체 지연; 소수 표본이면 참고값 |
| embeddingMs/searchMs | 서버가 보고한 질문 임베딩/검색 단계 시간 |
| manualReview | 근거 누락 질문의 실제 문단을 사람이 확인해야 함 |

`sectionHitRate`는 정확한 섹션을 찾았는지 보는 초기 지표이며, 정답이 필요한 모든 조건을 포함하는지·답변이 맞는지까지 검증하지 않는다. 같은 섹션 안에서도 중요한 예외가 다른 청크에 있을 수 있다. 사람이 검색 문단을 읽고 기대 근거를 청크/문장 수준으로 보강한다.

정보가 없는 질문도 의미가 비슷한 문단이 검색될 수 있다. `NO_EVIDENCE`만 정상 결과라고 강제하지 않으며, 유사도 임계값을 정답 확률처럼 해석하지 않는다. 최종 LLM의 추정 방지는 대화 기능 연결 후 따로 평가한다.

API 원문은 갱신될 수 있다. 보고서의 `documentVersion`을 보관하고, 재평가 전 현재 문서에 기대 섹션·조건이 있는지 확인한다. 테스트 질문에는 실제 사용자 정보를 넣지 않는다.

## 원문 전체 전달 vs RAG 비교 계획

아직 답변 생성 API가 연결되지 않았으므로 이 비교의 수치는 **미측정**이다.

- A: 선택한 공고의 동일 버전 전체 본문을 LLM에 전달한다.
- B: 같은 공고에서 검색한 근거만 같은 LLM에 전달한다.
- 질문, 이전 대화, 모델, 생성 설정, 답변 규칙을 고정한다. 입력 형식과 근거 길이 차이를 기록한다.
- 각 조건을 여러 번 교차 실행한다. 캐시 사용 여부를 기록하고 최초 호출과 반복 호출을 구분한다.
- 정답·예외 조건을 포함한 평가 기준으로 사람이 채점한다. 필요하면 LLM 평가를 보조로 쓰되 표본을 직접 검토한다.

| 비교 지표 | 계산·기록 |
|---|---|
| 답변 정확도 | 기준 충족 질문 수 / 전체 질문 수 |
| 근거 없는 주장 | 제공 근거로 뒷받침되지 않는 주장이 있는 답변 비율 |
| 첫 답변/완료 시간 | 사용자 요청 기준 각각 p50/p95 |
| 비용 | 실제 모델 사용량 기반 질문당 비용, 임베딩·DB·초기 색인 비용 별도 |
| 검색 누락 | B에서 필요한 근거가 빠진 질문 비율 |

검색이 빨라졌다는 사실만으로 아바타의 첫 음성까지 빨라졌다고 판단하지 않는다. 음성 인식·LLM·음성 합성 시간을 연결 후 분리 측정한다.

## 모델 비교

small과 large는 같은 원문 버전·질문·분할 규칙·K로 비교한다. 사용 차원을 기록하고 모델을 바꿀 때 재임베딩한다. 벡터를 섞어 검색하지 않는다.

## 검증 기록

- 도구·fixture 오프라인 검증: 구현 후 `--dry-run` 결과를 확인한다.
- 실제 공고 색인·검색 측정: 실행 전에는 미측정. 생성된 `backend/build/rag/evaluation.json`을 기준으로 요약을 기록한다.
- 최종 답변 A/B·아바타 지연 비교: 후속 작업.

- 월세 신청 방법과 취업날개 서비스 질문은 기대 섹션을 찾지 못했다. 검색 품질 개선이 필요하다.
- 정보가 없는 질문 3개도 `OK`와 관련 없는 후보를 반환했다. **유사도 임계값은 정보의 존재를 보장하지 않으며, 팀원의 LLM은 실제 근거를 확인하고 없으면 답변을 유보해야 한다.**
- 이 수치는 섹션 검색만 측정한다. 최종 답변 정확도·환각률·비용·원문 직접 전달과의 A/B 비교는 아직 측정하지 않았다. 실제 결과 파일은 `backend/build/rag/`에 저장했다.
